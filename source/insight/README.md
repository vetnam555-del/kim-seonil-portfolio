# 포트폴리오 방문 계측

누가 어디까지 읽고 무엇을 눌렀는지 본다. 쿠키를 쓰지 않고, IP 를 받지 않는다.

지금은 **꺼져 있다.** 아래 4단계를 마치고 환경변수를 넣어 빌드해야 켜진다.
켜기 전 산출물은 지금 배포본과 완전히 같다 — 확인은 `npm run build:general` 후
`grep -c 'id="insight"' out/index.html` 가 `0` 이면 된다.

---

## 누가 봤는지 아는 법 — 고유 링크

지원처마다 **다른 주소**를 보낸다. 열린 코드가 곧 누가 봤는지다.

```
에이블리에 보낸 주소   …/kim-seonil-portfolio/?r=k7f2
무신사에 보낸 주소     …/kim-seonil-portfolio/?r=q3mx
리멤버 프로필         …/kim-seonil-portfolio/?r=rmbr
```

`k7f2` 로 들어온 방문은 에이블리다. **그 주소를 받은 곳이 거기뿐이기 때문**이고,
방문자에게서 알아낸 것이 아니라 내가 어디로 보냈는지의 기록이라 헛짚지 않는다.
코드는 첫 페이지에서만 주소에 붙어 있지만, 방문 내내 따라다닌다(케이스 → 이력서로 옮겨도 유지).

**만드는 법**: 스프레드시트 `수신처` 시트에 지원처 이름만 적고
메뉴 **[계측] → [보낼 링크 만들기]**. 코드(짐작 불가능한 4글자)와 완성된 주소가 채워진다.

| 지원처 | 직무 | 보낸 날짜 | 메모 | 코드 | 보낼 주소 |
|---|---|---|---|---|---|
| 에이블리 | 마케터 | 2026-09-09 | 리멤버 339138 | `k7f2` | …/?r=k7f2 |

요약 시트 맨 위에 이렇게 나온다:

```
누가 봤나              방문  가장 깊이  읽은 시간  어디까지      마지막 방문
에이블리 · 마케터 (k7f2)   3    98%      2분 41초   증빙 원본     09-10 14:22
(코드 없는 방문)          1    17%      12초       첫 화면       09-10 09:15
```

### IP 로 회사를 알아내지 않는 이유

가능은 하다(Leadfeeder·Clearbit 류). 하지만 이 용도에는 맞지 않는다.

- **Apps Script 는 IP 를 아예 못 받는다.** 하려면 백엔드를 Cloudflare Worker 등으로 바꿔야 한다.
- **유료 서비스가 필요하고**, IP 는 개인정보라 처리 고지 의무가 생긴다.
- **정확도가 낮다.** ISP·모바일·VPN 이면 헛짚고, 회사를 특정할 수 있는 비율이 절반 남짓이다.
- 고유 링크는 **내가 보낸 곳에 대해서는 100%** 다. 링크는 언제나 내가 직접 배포하므로
  구직에는 이쪽이 더 정확하다.

한계는 하나다 — **내가 링크를 준 경우에만 안다.** 검색이나 전달로 들어온 방문은
`(코드 없는 방문)` 으로 남는다. 그건 그것대로 알아 둘 값어치가 있는 정보다.

## 무엇을 재는가

| 이벤트 | 언제 | 담기는 것 |
|---|---|---|
| `view` | 페이지 진입 (즉시 전송) | 경로, 유입 경로, 화면 크기, 언어 |
| `sect` | 본문 칸이 화면의 40% 이상 보일 때 (칸마다 1회) | 칸 id (`hero`·`case-jestina`·`case-results` …) |
| `depth` | 스크롤 25 / 50 / 75 / 100% 도달 | 깊이 |
| `dwell` | 머문 지 10 / 30 / 60 / 180초 | 초 |
| `out` | 링크 클릭 | 종류(`case`·`evidence`·`pdf`·`resume`·`mail`·`external`), 대상, 문구 |
| `end` | 페이지를 떠날 때 | 최종 깊이, 읽은 시간, 마지막으로 본 칸, 화면 크기 |

**읽은 시간은 탭이 보일 때만 센다.** 열어 두고 다른 일을 한 시간을 읽은 시간으로 세면 안 된다.

## 개인정보

- **쿠키 0개.** 세션 식별자는 `sessionStorage` 에만 있고 탭을 닫으면 사라진다. 같은 사람이 내일 다시 오면 다른 값이 된다.
- **IP 를 받지 않는다.** Apps Script 웹앱은 요청자 IP 를 스크립트에 넘기지 않는다. 받고 싶어도 받을 수가 없다.
- **지문(fingerprint)을 만들지 않는다.** 화면 크기와 언어는 조판 확인용으로만 보낸다.
- **Global Privacy Control** 을 켠 방문자는 아예 수집하지 않는다.
- 쿠키를 쓰지 않으므로 동의 배너가 필요 없다.

## 붙이는 법

### 1. 스프레드시트와 스크립트 만들기

1. Google 스프레드시트를 새로 만든다 (이름 예: `포트폴리오 계측`).
2. **확장 프로그램 → Apps Script** 를 연다.
3. `Code.gs` 의 내용을 붙여넣는다 (기본 `Code.gs` 를 덮어쓴다).
4. **파일 +** 로 스크립트를 하나 더 만들어 이름을 `summary` 로 하고 `summary.gs` 내용을 붙여넣는다.
5. 저장한다.

### 2. 웹앱으로 배포

1. Apps Script 오른쪽 위 **배포 → 새 배포**.
2. 유형 **웹 앱**.
3. **다음 사용자로 실행: 나**, **액세스 권한: 모든 사용자**.
   - 이 두 값이 아니면 브라우저가 보낸 비콘이 거부된다.
4. 배포하고 **웹 앱 URL** 을 복사한다 (`https://script.google.com/macros/s/…/exec`).
5. 그 주소를 브라우저에서 그냥 열어 `{"ok":true,"rows":0,…}` 이 보이면 정상이다.

### 3. 사이트에 켜기

빌드할 때 환경변수를 준다. PowerShell 기준:

```powershell
$env:NEXT_PUBLIC_INSIGHT_URL = "https://script.google.com/macros/s/여기에붙여넣기/exec"
npm run build:general
```

붙었는지 확인:

```bash
grep -c 'id="insight"' out/index.html    # 1 이면 켜짐
```

그다음 평소대로 `out/` 을 `portfolio-github-sync` 로 복사하고 commit·push 한다.

> **끄려면** 환경변수 없이 다시 빌드하면 된다. 스크립트가 아예 안 나간다.

### 4. 요약 보기

스프레드시트를 열면 상단에 **[계측]** 메뉴가 생긴다 (안 보이면 새로고침).
**계측 → 요약 다시 만들기** 를 누르면 `요약` 시트가 새로 그려진다.
같은 메뉴의 **보낼 링크 만들기** 로 지원처별 고유 주소를 만든다.

매일 자동으로 돌리려면 Apps Script 에서 **트리거 → 트리거 추가 →
`buildSummary` / 시간 기반 / 일 단위** 로 걸면 된다.

## 퍼널을 이렇게 잡은 이유

상거래 퍼널이 아니다. 평가하러 온 사람이 **어디까지 읽고 무엇을 눌렀는지**가 전환이다.

```
① 방문
② 히어로 통과 (25% 이상 스크롤)
③ 케이스 목록 도달
④ 케이스 상세 진입      ← 클릭이 필요한 첫 단계. 가장 비싼 행동이다.
⑤ 증빙 원본 열기        ← 가장 깊은 관심 신호
⑥ 이력서·PDF 열기
⑦ 메일 클릭
```

**②를 따로 둔 이유**: 첫 화면에서 나간 사람과 읽다가 나간 사람은 전혀 다른 신호인데,
방문 수만 보면 구분이 안 된다. 이 사이트에서 가장 알고 싶은 것이 바로 그 구분이다.

`이탈` 은 **한 쪽만 보고 · 25% 도 못 내려가고 · 10초도 안 머문** 세션으로 셌다.
세 조건을 모두 만족해야 이탈로 센다 — 30초를 읽고 나갔다면 그건 이탈이 아니라 정독이다.

## 한계 — 미리 알아 둘 것

- **방문자가 수십 명 규모다.** 비율(%)은 한두 명에 크게 흔들린다. 추세로 보고 소수점을 믿지 않는다.
- **같은 사람의 재방문을 묶을 수 없다.** 쿠키를 안 쓰기 때문이다. 이건 맞바꾼 것이지 결함이 아니다.
- **어느 회사가 봤는지는 내가 링크를 준 경우에만 안다.** 고유 링크(`?r=`)로 보낸 곳은 확실하지만,
  검색이나 전달로 들어온 방문은 `(코드 없는 방문)` 이다. IP 로 추정하지 않기 때문이다.
- **광고 차단기를 쓰면 안 잡힌다.** 자체 도메인이 아니라 script.google.com 으로 보내기 때문이다.
- `pagehide` 가 안 뜨는 경우(강제 종료 등)에는 마지막 20초분을 잃는다. 진입(`view`)은 즉시
  보내므로 방문 자체는 언제나 남는다.
