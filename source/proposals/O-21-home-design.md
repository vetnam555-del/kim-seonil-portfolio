# O-21 홈 디자인 방향 — 시안 A · B (2026-11-13)

주인 2026-11-13 "포트폴리오는 디자인이 뭔가 아쉬운 것 같은데". 아쉬운 곳으로 네 가지를 모두 골랐다.

| 고른 것 | 지금 홈에서 그렇게 보이는 까닭 |
|---|---|
| 첫 화면 뒤가 문서 같다 | 경력 · 일하는 순서가 흰 바탕에 글 단락으로만 이어진다. 구간이 바뀌어도 바탕이 바뀌지 않는다 |
| 성과가 그래프로 안 보인다 | 숫자는 크게 적혀 있지만 전 → 후의 크기 차이를 그린 것은 첫 화면 결과 칸의 가는 막대(6px)뿐이다 |
| 사례 이미지가 약하다 | 표지가 소재 모음 사진 한 장이다. 어느 브랜드의 무슨 결과인지는 사진 아래 글을 읽어야 안다 |
| 색 · 분위기가 단조롭다 | 첫 화면부터 대표 사례 끝까지 흰 바탕 · 검은 글 · 빨간 강조 하나다 |

진행 방식도 주인이 골랐다: **시안부터 본다** — 홈 핵심 구간(첫 화면 → 경력 → 일하는 순서 → 대표 사례)을 두 가지로 만들어 이미지로 보고, 고른 안만 사이트에 적용한다.
시안 이미지 세 장(지금 · A · B 비교판, A 전체, B 전체)은 2026-11-13 대화로 전달했다. **주인의 선택을 기다린다.**

## 두 시안

| | 시안 A · 밝은 매거진형 | 시안 B · 어두운 대시보드형 |
|---|---|---|
| 바탕 | 구간마다 바뀐다 — 흰색(첫 화면) → 종이색(경력) → 먹색(일하는 순서) → 흰색(사례) | 쪽 전체가 먹색. 내용은 테두리가 있는 패널에 담는다 |
| 첫 화면 | 지금 그대로 | 구조는 그대로, 색만 어둡게. 결과 세 칸이 타일이 된다 |
| 경력 | 흰 카드 세 장(로고 · 기간 · 역할 · 설명 · 핵심 두 줄) + 브랜드 · 매체 · 도구 칩 + 수상 카드 | 세로 타임라인 위의 패널 세 장 + 옆 기둥(Stack · Awards) |
| 일하는 순서 | 카드 세 장, 카드마다 세로 막대 그래프(전 = 회색 · 후 = 빨강) | 한 줄로 이어진 세 단계, 단계마다 큰 숫자 + 가로 막대 |
| 대표 사례 | 색면 표지(빨강 · 먹 · 종이 · 청록 · 회청) 위에 브랜드 이름 · 막대 그래프 · 비스듬히 놓은 소재 | 머리줄(번호 · 브랜드 · 태그) → 소재 이미지 → 지표 줄(큰 숫자 + 작은 막대) → 본문 |
| 강조색 | 빨강 하나(`#c7301b`), 어두운 띠에서는 `#ff5a3d` | 빨강(`#ff5a3d`) + 청록(`#4fd1cd` · 이름표) + 호박색(`#e8ae45` · 수상) |
| 적용 범위 | 홈의 세 구간. 소개 · 사례 · 이력서 쪽은 지금도 밝아 그대로 어울린다 | 홈 전체(머리띠 · 첫 화면 · 자동화 · 연락)와, 밝은 다른 쪽을 어떻게 맞출지까지 정해야 한다 |

Claude 의견은 **A**. 지금 첫 화면(창 크기 36가지로 맞춰 둔 것)과 밝은 다른 쪽을 그대로 두고 네 가지 아쉬움을 다 다루며, 긴 한글 본문은 밝은 바탕이 읽기 편하다.
B 는 인상이 더 강하지만 홈만 어두우면 다른 쪽과 끊기고, 전부 어둡게 하면 증빙 이미지 · 이력서 쪽까지 다시 맞춰야 한다. 정하는 것은 주인이다.

## 두 시안에 공통인 것

- 구간 순서와 내용은 지금 홈과 같다. **새 사실 · 새 숫자는 없다** — 문장과 숫자는 `content.mjs` 에 지금 홈의 것만 옮겼다.
- 시안에는 문장을 줄여 넣었다(경력 설명과 일하는 순서 본문의 뒤 문장, 단계별 역량 한 줄). 적용할 때 빠지는 문장을 지울지 · 다른 곳에 둘지는 따로 정한다 — 주인 확인 없이 사실을 지우지 않는다.
- 그래프는 화면에 적힌 두 값의 비만 그린다(0 기준). `+32.4%` · `+397.3%` 처럼 증감률만 있는 값은 기준 100 대비로 그리고 막대에는 숫자를 적지 않는다.
- 광고주 로고는 쓰지 않는다. 회사 로고는 지금처럼 작은 단색 세 개뿐이다.
- 그래프 색은 dataviz 검사기로 봤다: 색각 이상 · 일반 시야에서 전 · 후 구분은 모든 바탕에서 통과. 회색 막대는 밝은 바탕 · 색면에서 바탕과의 대비가 3:1 아래라, 막대마다 값이나 이름을 글자로 함께 적는다(값을 색으로만 읽게 두지 않는다).

## 시안에 없는 것 (고른 뒤 적용 단계에서 한다)

- 휴대폰 배치(390px 안팎) · 영문판 · 창 높이가 낮은 화면.
- 대표 사례 뒤의 구간(그 외 기록 · 자동화 · 연락)과 다른 쪽(방식 · 경력, 사례 상세, 이력서).
- 움직임(나타나기 · 숫자 올라가기), 그래프의 마우스 올림 설명, 키보드 초점.

## 다시 만들기

스크립트는 `proposals/O-21-home-design/` 에 있다. 빌드 결과의 사본 위에서만 돌린다(저장소 루트를 주면 `mock-*.html` 이 빌드 결과에 섞인다).

```bash
cd source
npm run build:general                      # out/ 이 지금 루트와 같으면 생략
rm -rf tmp/mock && mkdir -p tmp/mock && cp -r out tmp/mock/kim-seonil-portfolio
python3 -m http.server 8766 --bind 127.0.0.1 --directory tmp/mock &
M=proposals/O-21-home-design; S=tmp/mock/kim-seonil-portfolio; U=http://127.0.0.1:8766/kim-seonil-portfolio
for v in now a b; do node $M/render.mjs $S $U tmp/mock/shots $v 1440 2; done   # 전체 화면 세 장(2배 밀도)
node $M/compare.mjs $S $U tmp/mock/shots tmp/mock/compare.jpg                   # 지금 · A · B 비교판
```

- `render.mjs` 는 홈의 `index.html` 에서 스크립트를 빼고 세 구간만 시안의 마크업으로 바꾼 `mock-<a|b|now>.html` 을 사본 폴더에 쓴 뒤 찍는다.
  Playwright 가 없으면 HTML 만 쓴다 — 그 주소를 브라우저로 열면 된다. `tmp/` 는 커밋되지 않는다.
- 파일: `content.mjs`(문장 · 숫자 · 막대 그래프 만들기) · `variant_a.mjs` · `variant_b.mjs`(구간 마크업과 CSS) · `render.mjs` · `compare.mjs`.
