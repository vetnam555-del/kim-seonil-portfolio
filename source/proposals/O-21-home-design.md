# O-21 홈 디자인 방향 — 1차 시안 A · B → 보완안 C (2026-11-13)

주인 2026-11-13 "포트폴리오는 디자인이 뭔가 아쉬운 것 같은데". 아쉬운 곳으로 네 가지를 모두 골랐다.

| 고른 것 | 지금 홈에서 그렇게 보이는 까닭 |
|---|---|
| 첫 화면 뒤가 문서 같다 | 경력 · 일하는 순서가 흰 바탕에 글 단락으로만 이어진다. 구간이 바뀌어도 바탕이 바뀌지 않는다 |
| 성과가 그래프로 안 보인다 | 숫자는 크게 적혀 있지만 전 → 후의 크기 차이를 그린 것은 첫 화면 결과 칸의 가는 막대(6px)뿐이다 |
| 사례 이미지가 약하다 | 표지가 소재 모음 사진 한 장이다. 어느 브랜드의 무슨 결과인지는 사진 아래 글을 읽어야 안다 |
| 색 · 분위기가 단조롭다 | 첫 화면부터 대표 사례 끝까지 흰 바탕 · 검은 글 · 빨간 강조 하나다 |

진행 방식도 주인이 골랐다: **시안부터 본다** — 이미지로 보고, 고른 안만 사이트에 적용한다.

| 때 | 한 일 |
|---|---|
| 1차 | 홈 핵심 구간(첫 화면 → 경력 → 일하는 순서 → 대표 사례)을 A(밝은 매거진형) · B(어두운 대시보드형) 두 가지로 만들어 이미지 세 장 전달 |
| 주인 | "이게 최선의 방법이야? 더 없어? 확실해? 10점 만점에 10점이야?" |
| 2차 | A · B 를 정해 둔 결정과 '첫눈에' 기준에 다시 대조 → 아래 결함 → **보완안 C**(홈 전체 · PC와 휴대폰)를 만들어 이미지 세 장 전달 |

**지금 기다리는 것: 주인이 C 로 적용할지(또는 어두운 분위기를 원하는지) 정하는 것.**

## 1차 시안 A · B 가 10점이 아니었던 까닭

| 결함 | 무엇이 문제였나 |
|---|---|
| 문장을 줄였다 | 경력 설명 · 일하는 순서 본문의 뒤 문장과 단계별 역량 한 줄을 뺐다. 리멤버 업무 문장은 '본인이 확인한 그대로 쓴다'(2026-10-15)와 부딪힌다. 시안용 핵심 문구('명함 데이터 타겟팅' 등)도 새로 만든 말이었다 |
| 일부만 보였다 | 대표 사례 아래(그 외 기록 · 자동화 · 연락)와 휴대폰 화면이 없었다. 10점인지 판단할 수 없는 상태였다 |
| 꾸밈이 앞섰다 | A 의 비스듬한 소재 이미지와 다섯 가지 색면은 눈길은 끌지만 소재가 작아지고 작은 카드가 비좁았다. 칩(둥근 이름표)이 경력 · 브랜드 · 도구에 겹쳐 쌓였다 |
| 같은 그래프가 두 번 | 일하는 순서와 사례에 같은 막대 그래프(0.66% → 2.24%)가 따로 그려졌고, 첫 화면 결과 칸의 막대와 모양이 달랐다 |
| B 는 범위가 넓다 | 홈만 어두우면 밝은 다른 쪽(소개 · 사례 · 이력서)과 끊기고, 전부 어둡게 하면 증빙 이미지까지 다시 맞춰야 한다 |

A · B 의 설명과 스크립트(`variant_a.mjs` · `variant_b.mjs` · `content.mjs` · `render.mjs` · `compare.mjs`)는 견줘 볼 수 있게 남겨 둔다.

## 보완안 C

**원칙: 지금 홈의 마크업을 그대로 두고 그 위에 새 스타일을 입힌다.** 문장과 숫자를 다시 치지 않으므로 빠지거나 달라질 글이 없고, 적용할 때도 지금 부품(`HomeFolio.tsx` · `LoopStory.tsx`)과 검수 스크립트를 그대로 쓴다.

| 구간 | 지금 | C |
|---|---|---|
| 첫 화면 | — | 그대로(창 크기 36가지로 맞춰 둔 것) |
| 경력 | 첫 화면 구간 안의 세 칸 글 + 작은 글씨 목록 + 회색 띠 | 종이색 띠의 제 구간. 회사별 흰 카드 세 장(로고 · 기간 · 직함 · **문장 전부**, 핵심 사실만 굵게) + 큰 글씨 브랜드 목록 + 먹색 수상 패널 |
| 일하는 순서 | 1,862px 세로 한 줄(왼쪽 고정 목록 + 글) | 먹색 띠에 세 단계가 한 줄(1,082px). 단계마다 큰 숫자 + 막대 → 본문 전부 → 역량 한 줄 → 사례 링크 |
| 대표 사례 | 옅은 바탕의 소재 사진 + 글 | 색면 표지(번호 · 태그 · 기간 · 브랜드 이름 · 아래에서 올라오는 소재 이미지) → 결과 숫자 + 막대 → 수상 → 제목 → 설명 → 기여 범위 → 링크 |
| 그 외 기록 | 글 목록 네 줄 | 카드 네 장 |
| 자동화 | 흰 바탕 · 글 여섯 칸 | 종이색 띠 · 시스템 여섯 개를 카드로(번호 이름표 · 효과 줄) |
| 연락 | 먹색 | 먹색 + 인트로와 같은 점 무늬 · 붉은 빛 |

- **막대는 한 가지 표기만 쓴다** — 첫 화면 결과 칸에 이미 있는 것(회색 = 전 · 빨강 = 후, 0부터 같은 척도)을 일하는 순서와 사례에도 그대로 쓴다. 값은 바로 위 숫자가 말하고 막대는 크기만 보여 준다. 증감률만 있는 값(+32.4% · +397.3%)은 기준 100 대비.
- 새로 넣는 글자는 구간 이름표 `Career` 하나다(다른 구간의 `How I work` · `Selected work` 와 같은 자리). 왼쪽 고정 목록(FIND · TEST · IMPROVE)은 PC 에서도 숨긴다 — 태블릿 · 휴대폰에서는 지금도 숨기고, 같은 이름이 각 단계 카드에 있다.
- 색은 지금 사이트의 것만 쓴다: 먹 `#0b0d10` · 종이 `#f2efe8` · 빨강 `#c7301b`(어두운 바탕 `#ff5a3d`) · 청록 `#1a6f6b`(자동화 이름표 · 강원심층수 표지) · 회청 `#3d4552`.
- 광고주 로고는 쓰지 않는다. 회사 로고는 지금처럼 작은 단색 세 개뿐이다.

### 기계로 확인한 것 (`check_c.mjs`)

| 항목 | 결과 |
|---|---|
| 글이 빠지지 않았나 | 지금 화면의 글 조각 가운데 C 에 통째로 없는 것 0. 빠진 글자는 단계 이름 사이 가운뎃점 3개와(PC 에서만) 왼쪽 고정 목록의 중복 이름, 더한 글자는 `Career` |
| 가로 넘침 | 360×640 · 390×844 · 768×1024 · 1024×768 · 1280×585 · 1440×900 모두 0 |
| 글자 대비 | 다섯 구간의 글 201–204곳 가운데 기준(4.5:1 · 큰 글씨 3:1) 미달 0 |
| 누르는 곳 | 휴대폰에서 44px 보다 낮은 링크 · 버튼 0 |
| 쪽 길이 | PC 1440: 7,820 → 7,433px(−5%) · 휴대폰 390: 11,409 → 12,464px(+9%) |

### 아직 10점이라고 말할 수 없는 것

- 시안이다. 실제 원본에 옮긴 뒤 `qa_layout` · `qa_wrap` · 출시 계약(첫 화면 높이 · 낮은 창) · 동작 시험을 통과해야 한다.
- 움직임(막대가 자라기 · 표지 올림 · 숫자 올라가기)과 키보드 초점은 이미지에 없다.
- 영문판(글이 길다)과 다른 쪽(소개 · 사례 상세 · 이력서)은 아직 같은 모양이 아니다.
- 취향과 실제 방문자의 반응은 잴 수 없다 — 주인이 보고 정하고, 5초 테스트(O-18)로 확인한다.
- 휴대폰 쪽 길이가 9% 늘었다(카드 여백 · 표지). 더 줄이려면 표지 높이나 카드 여백을 낮춘다.

## 다시 만들기

스크립트는 `proposals/O-21-home-design/` 에 있다. 빌드 결과의 사본 위에서만 돌린다(저장소 루트를 주면 `mock-*.html` 이 빌드 결과에 섞인다). `tmp/` 는 커밋되지 않는다.

```bash
cd source
npm run build:general                      # out/ 이 지금 루트와 같으면 생략
rm -rf tmp/mock && mkdir -p tmp/mock && cp -r out tmp/mock/kim-seonil-portfolio
python3 -m http.server 8766 --bind 127.0.0.1 --directory tmp/mock &
M=proposals/O-21-home-design; S=tmp/mock/kim-seonil-portfolio; U=http://127.0.0.1:8766/kim-seonil-portfolio

# 보완안 C — 인자: <c|now> <폭> <높이> <밀도>
for v in now c; do node $M/render_c.mjs $S $U tmp/mock/shots $v 1440 900 1; done
node $M/render_c.mjs $S $U tmp/mock/shots c 390 844 2
node $M/check_c.mjs $U                                             # 글 · 넘침 · 대비 · 누르는 곳
node $M/compare_c.mjs $S $U tmp/mock/shots tmp/mock/compare-c.jpg  # 지금 → C 비교판

# 1차 시안 A · B
for v in now a b; do node $M/render.mjs $S $U tmp/mock/shots1 $v 1440 2; done
node $M/compare.mjs $S $U tmp/mock/shots1 tmp/mock/compare.jpg
```

- `render_c.mjs` 는 스크립트를 뺀 `index.html` 에 `variant_c.mjs` 의 스타일과 `augment()`(있는 요소를 옮기고 감싸기 · 막대 넣기) 한 번을 넣어 `mock-c.html` 로 쓴다. Playwright 가 없으면 HTML 만 쓴다 — 그 주소를 브라우저로 열면 된다.

## 주인이 정한 뒤 할 일 (C 기준)

1. 원본에 옮긴다. `variant_c.mjs` 의 CSS 는 `globals.css` 의 `.folio-*` · `.loop-*` 규칙으로, `augment()` 가 하는 일은 부품의 마크업으로:
   - `HomeFolio.tsx` — 경력 블록을 첫 화면 구간에서 꺼내 `section#career` 로(이름표 · 제목 · '수준별 역량 표' 링크 · 수상 목록 자리), 사례 카드의 표지 묶음(번호 · 태그 · 기간 · 브랜드 · 이미지)과 결과 블록 순서.
   - `LoopStory.tsx` — 세 단계를 한 줄로(왼쪽 고정 목록과 스크롤 강조는 뺀다), 단계 이름표 두 칸, 결과 아래 막대.
   - 막대는 첫 화면 결과 칸의 것(`folio-proof-bars`)을 같이 쓰는 부품 하나로. 값은 `site.ts` · `projects.ts` · `en/home.en.ts` 에서(국 · 영).
   - 경력 문장의 굵은 부분은 데이터에 표시한다(문장은 그대로).
2. 휴대폰 · 태블릿 · 낮은 창 · 영문판을 맞추고 `qa_layout` · `qa_wrap` · 출시 계약 · 동작 시험을 다시 통과시킨다. 움직임은 줄이기 설정(prefers-reduced-motion)을 따른다.
3. `npm run publish:general` → [글자 바뀜] 확인(홈에서 달라지는 글자는 이름표 `Career` · 단계 이름 사이 가운뎃점 · 왼쪽 고정 목록뿐이어야 한다) → typecheck · `qa_release` · 브라우저 증거 · RELEASE_PASS → 자비스 요청.
4. 이 폴더의 시안 스크립트는 적용이 끝나면 지운다(이 문서는 결정 기록으로 남긴다).
