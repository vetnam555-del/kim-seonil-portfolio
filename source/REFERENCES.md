# 레퍼런스 기록

다른 마케팅 포트폴리오를 계속 보고 배우기 위한 기록이다. 매주 월요일 정기 점검이 이 파일을 읽고 새 레퍼런스 1–2곳을
같은 기준으로 비교해 보고한다. 쓸 만한 아이디어는 `BACKLOG.md` 할 일(`R-` 번호)로 옮긴다.

## 원칙

- **형식만 가져온다.** 수치·경력·문장은 이 포트폴리오의 사실만 쓴다. 다른 사이트의 문장·이미지·디자인을 그대로 옮기지 않는다.
- **가져온 것과 안 가져온 것을 같이 적는다.** 안 가져온 이유가 있어야 같은 아이디어를 다음에 또 검토하지 않는다.
- **개인 사이트는 배울 점만 적는다.** 그 사람의 약점을 평가하거나 공개 저장소에 비교 점수를 남기지 않는다.
- **이 포트폴리오의 사례를 옮겨 쓴 것으로 보이는 사이트는 목록에 올리지 않는다**(BACKLOG O-05).
- **정해 둔 결정(BACKLOG "정해 둔 것")과 부딪히는 아이디어**는 할 일로 만들지 않고 주인 확인으로 둔다.

## 비교 기준

새 레퍼런스는 아래 여덟 가지로 본다. 각 항목에서 "우리보다 나은 점이 있는가"만 묻는다.

| 기준 | 묻는 것 |
|---|---|
| 첫 화면 | 누구인지 · 무엇을 하는지 · 증거 하나가 5초 안에 보이는가 |
| 사례 구조 | 문제 → 판단 → 실행 → 결과 → 배운 것 → 다음 판단 규칙이 이어지는가 |
| 수치 신뢰 | 기준·기간·분모·기여 범위·출처를 밝히는가, 비공개 수치를 어떻게 다루는가 |
| 말투 | 짧고 구체적인가, 상투어·명사 나열이 없는가 |
| 신뢰 장치 | 수상·언론·고객사·추천사·외부 링크를 어떻게 보여 주는가 |
| 탐색 | 홈 → 사례 → PDF·연락까지 몇 번 만에 가는가 |
| 직무·연차 맞춤 | 연차에 맞는 것을 앞세우는가(중간 연차: 사업 맥락과 협업 범위) |
| 속도·접근성 | 모바일에서 빠르고 읽기 쉬운가 |

## 참고: 검색에서 반복해 나온 공통 원칙 (2026-10-10)

- 사례는 4–6개로 줄이고 문제 → 실행 → 결과 구조로 쓴다. 이야기마다 수치 하나를 앞세운다.
- 비공개 수치는 비율 변화·비식별 고객 설명으로 보여 준다(우리: 비식별 증빙 + 기준 표기).
- 2026 채용 글들은 AI 도구를 썼다는 말보다 그 효과를 수치로 보여 주라고 한다(우리: 자동화 사례의 2시간 → 5분, AI 도구 범위 표기 — 이미 있음).
- 추천사·동료 평가가 신뢰 장치로 자주 쓰인다(우리: 없음 → R-03).
