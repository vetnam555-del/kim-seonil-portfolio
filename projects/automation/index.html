재고·소진·랜딩·리포트·정산을 정해진 주기로 확인하는 시스템 6종을 직접 만들어 운영하고 있습니다. 뉴발란스 등 여러 브랜드에 이 시스템을 적용했고, 담당자가 바로 이어받을 수 있도록 실행 스크립트와 운영 문서도 함께 정리했습니다.

전수 QA

01

문제 정의

사람이 기억해서 확인해야 하는 업무가 너무 많았습니다. 확인이 늦으면 광고비가 새고, 확인에 시간을 쓰면 판단할 시간이 없었습니다.

02

분석 근거

자동화에서 가장 위험한 실패는 멈추는 것이 아니라 잘못된 데이터로 계속 도는 것이었습니다. 재고 수집이 절반 실패한 상태로 판정을 진행하면 정상 판매 상품이 대량으로 꺼집니다. 그래서 판정의 방향을 뒤집었습니다 — 데이터가 좋다는 증거가 없으면 중단합니다.

03

전략

실행 속도보다 안전장치를 먼저 설계했습니다. 기준 파일 부재, 표본 0건, 재고 미상 비율 초과, 수집 실패율 초과 중 하나라도 걸리면 광고를 건드리지 않고 사람을 호출하는 fail-closed 구조입니다.

04

실행

  • 재고 연동 쇼핑검색 자동 운영 — 임계값 기반 OFF·재라이브, 2시간 주기, 회당 최대 900개
  • 리포트 자동화 엔진 — RAW 3종 붙여넣기로 대시보드·캠페인 리포트·QC 자동 생성, 매체 별칭 38종·오디언스 82그룹 자동 매핑
  • 무인 모니터링 3종 — 데드랜딩 점검(매일 2회), 소진 흐름(3시간 주기), GA4 데일리 코멘트(6개 매체)
  • 광고비 정산 자동화 — 법인카드 증빙을 전자결재에 자동 등록, 월 최대 84건 전량 처리(2026.05)
  • Auto Report 플랫폼 — 12개 KPI 시맨틱 레이어로 표준화해 월간 PDF 자동 발송 (Python · PostgreSQL · Docker)
  • 업무 지식봇 2종 — 업무 기록 854개 파일을 검색해 근거 파일과 함께 답하는 사내 챗봇

05

나의 역할

이 케이스의 기여도 100%는 뉴발란스 계정 운영 전체가 아니라 자동화 시스템 6종의 기획·구축·운영 범위입니다. 계정 운영 기여도 40%와 분리해 표기했습니다.

직접 수행

  • 6종 전체의 요건 정의 · 아키텍처 설계 · 코드 작성 · 배포 · 운영
  • fail-closed 4단 관문과 중단 기준 설계
  • LLM 교차검증 발행 규칙
  • 실행 스크립트와 인수인계 문서 작성

함께 수행

  • 전자결재 연동은 사내 시스템 담당 부서와 함께 규격을 맞췄습니다

하지 않은 것

  • 사내 인프라 계정 권한과 보안 정책은 정보시스템 부서 소관입니다
  • 매체 API 사용 계약·한도 협의는 제 범위가 아니었습니다

기여도100%

06

배운 것

되지 않았던 것

초기 설계는 실행 속도를 우선했습니다. 재고 수집이 절반 실패한 상태로 판정이 돌면 정상 판매 상품이 대량으로 꺼진다는 걸 확인하고 나서야 fail-closed로 방향을 뒤집었습니다. 자동화에서 가장 위험한 실패는 멈추는 것이 아니라 잘못된 데이터로 계속 도는 것이었습니다.

다음에 다르게 할 것

자동화는 사람을 대체하는 게 아니라 사람이 판단할 시간을 만드는 일이었습니다. 그래서 '이상하면 멈추고 부르는' 설계가 속도보다 중요했습니다.

07

증빙

스케줄러 설정 화면과 실행 로그로 보유하고 있으며, 광고주 데이터가 포함되지 않는 범위에서 인터뷰 시 보여드릴 수 있습니다.

08

출처

자동화 스케줄러 설정값, 운영 로그, 정산 처리 집계. 광고주 데이터·계정·거래처 정보는 포함하지 않았습니다.
