발행 속도보다 '무엇을 싣지 않을지'를 먼저 정했습니다

한 줄 요약

마케팅 뉴스는 많지만 확인된 사실과 단독 보도가 섞여 있습니다. 매일 낼 것을 정하기 전에 뺄 기준부터 만들었습니다. 출처 등급을 나누고, 공식 발표가 아닌 건은 서로 다른 매체 2곳에서 교차 확인되지 않으면 싣지 않습니다. 2026년 5월 19일부터 2026년 8월 25일까지 76호를 발행했고, 아카이브를 공개해 누구나 직접 확인할 수 있게 뒀습니다.

기간

근거 형태 — 공개 아카이브 (링크 확인 가능)

  • 누적 발행 76호
  • 회당 산출물 뉴스레터 1 + 카드 8장
  • 공개 아카이브 75호

마케팅 담당자가 하루 한 번 읽고 판단에 쓸 수 있는 뉴스레터와 인스타그램 카드뉴스를 평일마다 발행하는 것을 원칙으로 삼았습니다. 소재 선정부터 교차 검증, 카드 렌더, 발송, 아카이브 게시까지 한 사람이 설계하고 운영합니다.

01

문제 정의

속보를 빨리 옮기는 것은 어렵지 않습니다. 문제는 단독 보도와 교차 확인된 사실이 같은 무게로 유통된다는 점이었습니다. 매일 내야 하는 주기에서는 확인을 건너뛸 유인이 특히 큽니다.

02

데이터에서 확인한 것

소재 후보마다 에이전트 9~10개를 동시에 띄워 각각 독립적으로 웹 검색·교차 확인하고, 그 결과로 verified 여부와 확신도를 매깁니다. 정부·공공기관·기업 공식 발표는 1출처를 허용하고, 그 외 매체 보도는 서로 다른 2곳에서 확인되거나 원자료가 있을 때만 채택합니다.

03

핵심 판단

규칙을 사람의 성실함에 맡기지 않았습니다. 발행 전 lint 게이트가 VOL·날짜 불일치, 출처 누락, 요일 표기 오류를 잡고 에러가 하나라도 있으면 발행을 막습니다. 콘텐츠는 날짜별 단일 소스 파일 하나에서 뉴스레터·카드·캡션·대체텍스트가 전부 생성돼, 같은 수치가 두 곳에서 달라질 수 없습니다.

04

실행

  • 소재 후보 병렬 교차 검증 → verified·확신도 판정 → 채택/보류 분리
  • 출처 등급 규칙 적용(공식 발표 1출처 / 그 외 2개 매체 교차 또는 원자료)
  • 날짜별 단일 소스 파일에서 뉴스레터 HTML·카드 8장·캡션·대체텍스트 동시 생성
  • 발행 전 lint 게이트 통과 필수 — 에러 시 발행 차단
  • 이중 발행 방지 lock 파일로 같은 날 재발송 차단
  • 모바일 320·375·414px 가로 스크롤 검수 후 발송, 아카이브는 기사·매니페스트 먼저 게시하고 인덱스를 마지막에 갱신

무엇을 싣고 무엇을 빼는가

출처의 성격에 따라 채택 조건을 다르게 뒀습니다. 규칙을 먼저 적어 두면 매일 반복되는 판단이 흔들리지 않습니다.

모바일에서는 좌우로 밀어 확인할 수 있습니다.

무엇을 싣고 무엇을 빼는가
출처채택 조건이유
정부·공공기관 발표1출처 허용발표 주체가 곧 원자료입니다
기업 공식 발표1출처 허용당사자 발표로 확인 가능한 범위만 인용합니다
매체 단독 보도서로 다른 2곳 교차 확인 또는 원자료 확인단독은 확인이 아니라 주장입니다. 교차되지 않으면 싣지 않습니다

같은 브리핑을 두 매체가 서로 다른 수치로 보도한 건은 양쪽 다 제외하고, 교차 확인된 사실만 남겼습니다.

발행을 막는 게이트

품질을 사람의 성실함에 맡기지 않습니다. 광고 자동화에서 쓴 '이상 시 중단' 원칙을 그대로 옮겼습니다.

  1. 01

    ① 단일 소스

    날짜별 파일 하나에서 뉴스레터·카드·캡션·대체텍스트가 생성됩니다. 같은 수치가 두 곳에서 달라질 수 없습니다.

  2. 02

    ② lint 게이트

    VOL·날짜 불일치, 출처 누락, 요일 오표기를 잡습니다. 에러가 하나라도 있으면 발행이 막힙니다.

  3. 03

    ③ 렌더 검수

    모바일 320·375·414px 가로 스크롤과 사진 워터마크를 눈으로 확인합니다.

  4. 04

    ④ 이중 발행 차단

    그날의 lock 파일이 있으면 즉시 중단합니다. 같은 호를 두 번 보내지 않습니다.

게이트가 잡는 것은 형식 오류입니다. 사실 오류는 ①의 교차 검증 단계에서만 걸러집니다. 그래서 검증을 게이트 앞에 뒀습니다.

06

나의 역할

소재 선정 기준, 편집 규칙, 디자인 시스템, 렌더 파이프라인, 검증 게이트, 발송·아카이브 절차를 전부 직접 설계하고 운영합니다.

직접 수행

  • 편집 기준과 출처 등급 규칙 수립
  • 카드뉴스 디자인 시스템과 템플릿 엔진
  • 발행 차단 게이트(lint)와 이중 발행 방지 설계
  • 발행일마다 소재 선정·검증·발행

하지 않은 것

  • 기사 원문을 취재하지 않습니다. 공개 보도와 공식 발표를 교차 확인해 편집하는 범위입니다
  • 구독자 확보를 위한 유료 집행은 하지 않았습니다

기여 범위기획·편집·구축·발행 100% 단독

07

실패와 배운 것

되지 않았던 것

표지 사진 후보에 매체 워터마크가 박혀 있는 것을 첫 렌더에서 놓쳐 그대로 노출된 적이 있습니다. 크롭 영역을 조정해 재생성했고, 이후 사진 후보는 렌더 결과를 눈으로 확인하는 절차를 추가했습니다. 협약식 날짜를 보도일과 혼동해 잘못 적은 것도 발행 후 정정했습니다. 게이트가 잡는 것은 형식 오류지 사실 오류가 아니라는 걸 확인한 사례입니다.

다음에 다르게 할 것

매일 내는 매체에서 품질을 지키는 것은 의지가 아니라 차단 장치의 문제였습니다. 확인되지 않은 건을 빼는 판단이 가장 어렵고, 그래서 그 판단을 사람 손에 남겨 두지 않고 규칙과 검수 단계로 옮겼습니다. 광고 자동화에서 배운 '이상 시 중단' 원칙을 편집에도 그대로 적용했습니다.

08

실행 화면과 증빙

  • EDIT H 공개 아카이브 ↗

    공개된 발행본 75호와 출처 링크를 함께 보존합니다. (VOL.033 게시 대기)

공개 자료는 실제 운영·집행 맥락을 확인할 수 있는 범위만 선별했으며, 제작물과 개인 기여 범위는 캡션에서 구분했습니다.

배포 규모는 고정 목록 기준으로 작습니다. 도달·구독자 수를 성과로 적지 않았고, 확인 가능한 것은 발행 지속성과 편집 기준입니다.

09

근거와 산정 기준

집계 범위와 원자료 출처 보기＋

공개 아카이브 75호와 저장소의 제작·발행 76호 기록·게이트 로그 기준입니다. VOL.033 은 제작·발행됐으나 공개 아카이브 게시 대기 상태입니다. 구독자 명단과 발송 계정 정보는 포함하지 않습니다.
